# Original PID1 finalization contract

Read 2026-10-01 at Corenius commit `963f58b31e518a8162dfe719e386ef9d9843321f`. This is bounded diagnosis evidence for the proposed supervisor repair, not implementation or acceptance. [Structured observations](../evidence/pid1-finalization-observations.json) retain all three launch dispositions, source URLs/hashes and actual sequences. The host is vendor Linux `5.15.152.bsk.9-amd64`, bubblewrap0.8.0. Upstream v5.15 source is authoritative upstream behavior, not an attestation of the vendor's exact patched source.

## Source ordering and proposed certificate

[Linux v5.15 pid_namespace.c](https://raw.githubusercontent.com/torvalds/linux/v5.15/kernel/pid_namespace.c), zap_pid_ns_processes, disables PID allocation, signals namespace tasks and waits for child/task removal before namespace init finalization. [exit.c](https://raw.githubusercontent.com/torvalds/linux/v5.15/kernel/exit.c) invokes that teardown through find_child_reaper/forget_original_parent before assigning EXIT_ZOMBIE and notifying the parent. exit_files and exit_task_namespaces precede that wait. Consequently absent ns/pid links can occur before namespace shutdown completes; nslink ENOENT/ESRCH is not the finalization certificate.

Proposed contract: while the workload is gated, establish and persist the original namespace PID1 through NSpid ending1, host PID, boot ID and start ticks. Bind any pidfd to that exact process before trusting readiness; a PID-only fd opened after PID reuse is insufficient. Whole-process pidfd readiness or authoritative reaping of that original PID1 can certify the teardown boundary. [pidfd_open documentation](https://man7.org/linux/man-pages/man2/pidfd_open.2.html) distinguishes whole-process readiness from thread readiness. A generic leader Z observation is insufficient unless trusted PID1 is known single-threaded; leader exit can precede last-thread exit. A live D/S state, observation error or namespace identity mismatch does not certify completion. Stat disappearance/replacement must be classified independently of namespace-link failure and with the recorded boot/start identity and correct host /proc assumptions.

With verified finalization and enforced no-escape capsule boundaries, external reconciliation can establish stopped without signaling members found under a potentially reused namespace inode. While original membership is live, acquire an independently verified namespace pin for inventory/signaling. If neither certificate nor trustworthy live pin is available, preserve quarantine and capacity. Kernel task teardown does not prove completion of previously submitted external asynchronous effects; those require separate service/effect accounting. This is an inference from the kernel ordering and capsule assumptions, not observed production behavior.

## Actual bounded corroboration

Exactly three owned bwrap launches occurred, one active at a time. Launch1 failed creating an absent /fixture mountpoint under the read-only root; the probe failed and made no successful workload claim. Launch2 corrected the owned mount path and exited0: info child-pid2001988 had NSpid `2001988 1`, start26863001. Controller returned -9 after SIGKILL; original PID1 S was followed by stat ENOENT and bound pidfd POLLIN. Heartbeat output remained15bytes after exit and over50ms.

Launch3 additionally used --block-fd0. Before unblock, child-pid2004583 had NSpid `2004583 1`, start26865240, and no effect file. After release, a background shell loop and its sleep descendants wrote heartbeat output. Controller SIGKILL returned -9; original PID1 S/S was followed by stat ENOENT and bound pidfd POLLIN. Output remained15bytes after exit and over50ms. The [retained probe](probes/pid1_finalization_probe.py) reproduces this third configuration; earlier launch variants are described rather than falsely attributed to the final script.

The probe reads actual stat/status/namespace links and holds a whole-process pidfd opened for the observed gated PID1. It does not retain a namespace FD during controller loss. Owned temporary directories were removed; controllers were waited; PID1 exit was observed. The observed short write-cessation interval corroborates this fixture only. No D-state delay, multithreaded init, permission race, arbitrary escape, external I/O, broker integration or crash durability was demonstrated. No model, provider, app-server or shared configuration was launched/modified.
