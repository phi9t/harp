# Independent critique: changed synthetic budget repair

This critiques preparation/admission design, not runnable guards (not yet supplied).

## Blocking admission gaps

1. **Three TOTAL attempts leaves no discovery/error allowance.** Decision line 9 budgets three incoming HTTP attempts across two incarnations, and line 11 asks HTTP failure, truncated stream and success. Those three cases require at least one HTTP request each; any model discovery GET, warmup, reconnect probe or denied retry consumes an attempt and prevents all three scenarios. Old provider script includes GET discovery. Before admission declare exact case/turn/incarnation mapping and prove offline that configuration needs no discovery, or explicitly permit incomplete scenario coverage on the first discovery/extra attempt. Do not add a free discovery category or replenish budget. Starting a second incarnation after the shared third attempt is exhausted must be prohibited even if two-incarnation budget remains.

2. **Proxy cannot prove literal client-attempt suppression.** Lines 9 and 11 correctly call denied retries failures, but “stops ... on exhaustion” does not make a hard three-attempt guarantee. A fourth connection/request can be buffered, concurrently accepted, or already in flight while supervisor stop propagates. A sole-egress proxy can atomically cap admitted/forwarded attempts at three; it cannot alone establish that Trae never attempted a fourth. Pre-admission contract must distinguish (a) requests observed at the guard, (b) network send/connection attempts, (c) forwarded requests. Exactly define the incoming-request counting point and evidence coverage after namespace shutdown. If line 9 means an inviolable physical total rather than a measured failure condition, capability is not yet established and admission stays blocked. No claim that stopping after count three makes count four impossible.

3. **Retry suppression remains a hypothesis.** Line 11 properly says custom keys are hypotheses. Freeze exact provider ID, transport, retry override hierarchy, model/turn selection and finite cap; establish parser acceptance/effective nonsecret values independently of ordinary config origins. Reserved built-in provider IDs and ordinary turn precedence must be resolved. Offline tests should exercise retryable HTTP and mid-stream truncation in the **same exact transport/guard path**, but mock-client passing tests cannot prove pinned Trae suppression. The first actual retry failure is terminal for this round; no second incarnation aimed at refining a failed guess.

4. **Exhaustion timing conflicts with third-case success unless defined.** If guard stops namespace immediately on third reservation, it can kill the valid success before terminal SSE consumption. If it waits for terminal completion, a fourth attempt can race during that interval. Define final response publication, terminal completion observation, dispatch revocation and bounded supervisor stop ordering. Failure-path timeouts must still stop when no terminal notification arrives. Design can prove successful third response plus later stopped inventory, or immediate exhaustion stop; do not assert both without exact sequencing evidence.

5. **Valid SSE must be judged by runtime behavior.** Line 11 demands valid bounded Responses success. Offline byte-size/event-order tests are useful but not sufficient. Retain request body model/stream/cap fields, event sequence, matching response/item IDs, completion/usage fields, and Trae terminal success with exact synthetic content and no tools/extra requests. Model selection must match the deliberately chosen finite synthetic model; a discovery advertisement alone did not establish selection in old run. HTTP status200 or valid JSON/SSE framing is insufficient. Truncated-stream test must identify where it truncates, ensure client recognizes failure, and retain all retries/notifications after complete shutdown.

## Precise pre-admission checks

- Freeze script/config/guard/protocol digests and separately retain original nine-attempt failure (decision lines 5,7). Old LAUNCH_ENABLED refusal remains intact.
- Offline public guard tests: three-way concurrency at shared last slot; rejected oversized/chunked/malformed requests; HTTP body-length mismatch; atomic record/reservation publication; service crash/restart without counter reset; second incarnation shares durable cumulative ledger; fourth attempt recorded as failure with zero forwarding; synthetic response-byte caps and bounded event behavior. Reservations occur before body-dependent upstream effects and cannot be refunded by uncertain/crashed execution.
- Define whether one MiB limit includes encoded request body only and how missing Content-Length/chunked encoding are rejected; parsing limits must act before unbounded memory reads. Discovery and all routes must consume shared attempted count even if rejected.
- Sole permitted egress is owned synthetic endpoint; external upstream forwarding disabled structurally. Immutable operation ID plus namespace/incarnation/turn attribution is persisted before dispatch; establish owner-only ledger and proxy independence from child runtime.
- Independently supervised PID namespace/cgroup evidence must include every descendant, durable timeout/stop handling and empty inventory after stop. Stop acknowledgement or launcher PID exit alone fails SPEC lines 160–163,275–280.
- Admit only once precise counting/stop semantics and retry/model/SSE configuration are reviewable. Automatic continuation, guessing a replacement provider or retrying a failed probe violates decision lines 9,15.

## Feasible claim and limits

Feasible: offline guard proves at most three admitted/forwarded synthetic requests with durable shared accounting; actual bounded probe either observes three or fewer incoming requests and successful/failure cases, or records explicit extra-attempt violation then stops all effects. This matches decision line 15 only if extra attempt is treated as measured failure, not a successful hard envelope. Impossible proxy-only claim: client cannot issue attempt four because guard will return a refusal or stop asynchronously.

External ordinary hard cost remains excluded (decision line 13). Finite request field does not independently establish provider cap enforcement, aggregate token cost or billing cessation; local SSE interruption does not stop remote generation. SPEC lines313–319 require finite cumulative budget and unknown usage retained. Synthetic zero-spend isolation proves no external paid traffic, not external cost readiness.

Verdict: offline preparation is within lines7–9; additional runtime admission is premature until these gaps are reconciled in exact frozen guard/config and reviewed. Full-goal authorization does not supply missing retry/protocol capability.
