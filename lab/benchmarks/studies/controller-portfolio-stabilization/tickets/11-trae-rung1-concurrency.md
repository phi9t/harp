## What to build

Run the TraeCLI analogue of the controlled trial with one TraeCLI Lead and two overlapping TraeCLI workers, proving capacity, stale-Candidate rework, independent verification and serialized disposable-repository landing.

## Acceptance
- [ ] Two workers run useful overlapping Attempts in isolated worktrees and a third admission is rejected while both slots or an unknown execution consume capacity.
- [ ] Both initial Candidates share the same base; the approved first Candidate advances only the disposable protected ref through the authenticated operator path.
- [ ] The second Candidate is rejected as stale and a new Attempt produces and verifies a new Candidate at the new base.
- [ ] Old evidence cannot accept the reworked Candidate; review-driven rework retains both histories.
- [ ] Controller events, work-ledger state, Git refs, runtime observations and cleanup receipts agree at terminal state.
