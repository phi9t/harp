What system is being improved?

Matching Weng section: introduction and coding-agent case study. Read the public original.

Learner win

Given a system change, identify whether it edits model weights, the training pipeline, or the deployment harness, and state what extra evidence a successor claim needs.

Start with the edited boundary

Model weights
The checkpoint changes through training or fine-tuning.
Training pipeline
Data, objectives, code, or evaluation machinery that produces a checkpoint changes.
Deployment harness
Context, tools, memory, control flow, subagents, verification, or persistence around a checkpoint changes.

A successor boundary is stricter: an externally accepted child must become the next parent. Immediate task gain is not evidence that the child is better at producing another valid child.

Source cards

GOOD-1965 and YUDKOWSKY-2008 frame recursive successor improvement conceptually. ASP, ABSOLUTE-ZERO, SELF-REWARDING, and SPIN report bounded self-play or weight-training results; they are adjacent evidence, not harness-improvement demonstrations.

KARPATHY-AUTORESEARCH is a concrete harness-design pattern. ANTHROPIC-RSI is company framing that explicitly says the system is not yet RSI.

Compare: Absolute Zero and Autoresearch

Absolute Zero changes reasoning-model weights through proposer–solver reinforcement learning under executable verification. Autoresearch changes a training program, then each experiment trains candidate weights for a fixed five-minute window and scores validation bits per byte. In both cases, objectives, evaluators, budgets, permissions, and promotion rules remain externally fixed. Neither source tests whether an accepted child improves the next successor-production cycle.

Free recall

Without looking back, classify these changes: a LoRA update; an edit to train.py; adding a tool retry policy; accepting a checkpoint and asking it to redesign the next training run. For the fourth, name the missing matched evidence before calling it recursive improvement.

A fixed checkpoint gains a filesystem memory and a verifier. What changed?
