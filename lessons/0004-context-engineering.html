Context engineering

Matching Weng section: Context Engineering. Read the public original.

Learner win

Classify a context system by its exact edited object: artifact, mechanism, or executable harness code.

Artifact → mechanism → code

The final prompt does not identify which layer changed. Record provenance for the artifact, update mechanism, and executable policy separately.

A stored item may exist but remain ineligible, unselected, badly rendered, never activated, or abandoned. A useful evaluator must distinguish those failures from bad content.

Source cards

  1. ACE edits a structured context artifact: an itemized playbook updated from rollout feedback.
  2. MCE edits context-engineering skills and procedures that construct or update context.
  3. META-HARNESS searches executable context-management harness code that stores, retrieves, transforms, and presents information.

Fixed boundaries

These sources do not support silently attributing every gain to model intelligence. ACE and MCE operate around fixed base-level models in their reported setups. Meta-Harness fixes the base model while an outer proposer and evaluator search harness candidates. Task rewards, held-out evaluations, budgets, and promotion remain outside the editable object.

In Meta-Harness, the outer proposer, search tasks, and held-out evaluator remain controls beyond the candidate harness's editable code.

Card recall and discrimination

Card recall: Close the source-card page and state the edited object, persistence form, and evaluator for ACE.

Discrimination: A system rewrites the function that chooses memories for a prompt. Is the primary edit the memory item, the context-construction procedure, or model weights? What additional evidence would show that this procedure improves held-out behavior rather than only increasing context or calls?

A candidate changes the skill that selects and compresses stored items, but not the items or weights. What is the closest edited layer?
