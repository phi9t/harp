Harness design patterns

Matching Weng section: Harness Design Patterns. Read the public original.

Learner win

Distinguish a transient execution loop from persistent adaptation and explain why inspectable state is necessary but not sufficient for improvement.

Three prerequisites

  • Loops: expose plan, execute, test, decide, and stop transitions.
  • File persistence: retain artifacts, checkpoints, logs, and handoffs where later runs can inspect them.
  • Subagents or backend jobs: provide bounded specialization or parallel work, with explicit ownership and resource accounting.

These patterns make state inspectable and recovery possible. Persistence alone is not improvement: a stored artifact must be consumed later and causally beat a no-update control.

Source cards

In KARPATHY-AUTORESEARCH, the agent edits train.py; the human edits program.md. Each run trains for five minutes, reports val_bpb (validation bits per byte), and ends in a keep, discard, or crash decision. Git state and an experiment log persist. The objective, evaluator, data, time budget, permissions, and agenda remain fixed outside the agent.

This is an inspectable training-program search pattern. It does not by itself establish a better research process, agenda autonomy, or recursive successor gain.

Compare the state

Transient transcript
A retry or critique exists only in the current run and disappears afterward.
Durable artifact
A versioned edit, checkpoint, or failure record survives and can affect a later run.

Compare-or-classify

Classify each as task iteration, persistent adaptation, or neither: retry after a failed test; write the failure to a file that no later run reads; load the file in the next run and avoid the failure; fan out three child agents. State what causal comparison is still needed.
