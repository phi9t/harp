## 6. Patterns worth standardising

1. Frontmatter. Baseline `name` + `description` (all). Extensions seen: `when_to_use` (megatronlm), `argument-hint`, `user_invocable`/`user-invocable`, `disable-model-invocation` (roborev, sglang, torchtitan: manual-only), `tools`/`model` (agents), `metadata`, `license`. Inconsistent spellings: `user_invocable` vs `user-invocable`. Recommend a schema and a validator (`bytedcli-dev validate skills` and skill-creator `quick_validate.py` are starting points). Descriptions in about 60% are "Use when..." triggers; the rest are titles and will under-trigger (inferred).
2. Destructive-action gating. Best practices found: land-on-mainline (local-only by default, push only when asked, refuse dirty tree, no `--no-ff`); arnold lending (dry-run, readback, on-the-spot credentials); mr-review-loop (Disposition Ledger); harbor publish (confirm); torch_bisect (confirm); modular sanitize (pre-push scan). Missing: any machine enforcement. No PreToolUse hooks, so gates are prose only.
3. Verification requirements. Strongest: milano (fresh gates on the exact commit, evidence receipts, content-addressed), feature-e2e-verify (per-hop causal evidence), mechanical-refactor-verify (byte-for-byte proof), fix-ci (read real log, not local guess), Superpowers `verification-before-completion`. Standardise: claims cite fresh command output from the final state.
4. Skill layout. `SKILL.md` + `references/` + `scripts/` + `tests/` + `evals/` + `agents/openai.yaml` (arnold, bytedcli). Arnold adds `docs/skills/<name>/{usage,implementation,lark-sync}.md`. Keep SKILL.md short and push detail to references (bytedcli mr-reviewer at 648 lines and megatron nightly-sync at 608 are too long).
5. One source, many agents. roborev generates claude/codex/droid/grok variants from one source; `.agents/skills` vs `.claude/skills` is split by repo with no rule. Standardise on `.agents/skills` as canonical with `.claude/skills` symlinks (inferred: Claude Code reads `.claude/skills` only).
6. Policy sync. `docs/agents/*` sets carry a "managed by Corenius" header and version (crosswalk v2026.09.29.1) across 12 repos. That is already the shared-distribution mechanism; skills should follow it.
7. Tested skills. Only arnold `tce-status-query` and `arnold-targeted-lending`, bytedcli `mr-review-loop` (`evals.json`), `workflow-to-cli`, and `shuorenhua` (benchmarks) ship tests or evals. Most skills have no eval.
