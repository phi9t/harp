## Implemented public contract

The typed MailboxService command/read boundary is backed by additive0006. Current
bearer role, mission/task scope, task generation, external recovery epoch and Lead
session generation are checked before cached-command results. Immutable applied
and rejected dispositions bind principal/family/key and normalized arguments;
correcting a rejection requires a new key. Lead replacement fences predecessor
credentials without expanding or revoking Worker/Verifier task authority.

Messages retain authenticated sender/role/attempt, approved digest/revision and
epoch. Persistence, exact input/episode presentation, explicit recipient
acknowledgment and question resolution are distinct records. New active-episode
input coalesces without charging another simultaneous episode. Questions survive
conversation replacement through canonical outgoing references/logical Lead
addressing; private incoming predecessor conversations are not disclosed.

CaptureInput stores a bounded immutable canonical packet containing approved
mission constraints, own approved task/attempt, exact pending message membership,
content digest and event frontier. Admission checks the current caller, packet,
purpose, generation/epoch and frontier before budget charge. Existing unseen
limit=1 batches can advance at the same frontier; repeated/consumed packets and
empty captured or legacy repeats cannot buy polling episodes. First assigned
Worker admission imports its existing charge once; continuations, planning and
independent verification spend finite episode budgets. A Verifier needs the
independently assigned actual current candidate and never gains execution role.
Legacy caller-digest-only admission is explicitly `caller_asserted_logical` and
cannot bind a physical runtime turn; captured packets are required for every
physical binding in this candidate. No unverified caller digest is represented
as broker-captured model input.

Owner/controller binding requires the exact confirmed gateway Start packet and
adapter-proven immutable native turn identity. Durable PrepareDelivery records
message/episode/input/expected turn and exact workflow incarnation before I/O.
The existing gateway queue and same PostgreSQL dispatch-claim transaction check
current episode/authority/deadline, workflow incarnation and optional canonical
approved decision/exact consumed permission after the runtime mutex. Runtime
steering requires atomic native expected-turn capability, not a generic steer
boolean. Authoritative turn completion leaves pending input for a later bounded
logical episode; uncertainty never retransmits a non-idempotent operation.
Confirmation does not synthesize presentation, acknowledgment, task acceptance,
external-process stop or reservation refund.

Yield atomically records bounded checkpoint/artifact references, questions,
task dependencies, typed unresolved Execution references, episode closure and
waits plus the existing registry/outbox wakeup. Answers before/during/after yield
retain durable satisfactions. Accepted13's existing Activity/progress transaction
reads separate mailbox attention IDs and repairs canonical accepted-task waits.
The workflow schedule/input stays unchanged; Progress's new field has a serde
default for old histories. There is no second scheduler or task-status authority.

Replacement context is bounded and paginated from canonical constraints, approved
specs/admitted revisions, decisions/proposals, checkpoint/evidence references,
unanswered questions, attempts/uncertain gateway state and budget. Proposals do
not change approved tasks/assignments. Decisions precede dependent dispatch.
Approvals bind exact normalized operation arguments, named executor, scope,
generation/epoch, expiry and one consumption; Owner-granted canonical permissions
survive loss of the requesting Lead conversation. They record permission only,
not a protected external integration/publication effect.

HTTP and pinned MCP2025-11-25 Streamable HTTP use the same caller boundaries,
including initialize/initialized/session handling, tools/resources/templates,
scoped task input and ArtifactService publication/submission/verification.
The optional absolute TEAM_CONTROL_PLANE_ARTIFACT_ROOT configures the actual
executable facade. WorkerA/taskA -> WorkerB/taskB addressed registered exact
artifact bytes are equal via HTTP/MCP before source-task acceptance; arbitrary
registered digests, direct unscoped objects, peer task/history and unauthorized
Verifier submission remain denied. Same-task Verifier permission is not used as
a substitute for this distinct peer disclosure grant.
