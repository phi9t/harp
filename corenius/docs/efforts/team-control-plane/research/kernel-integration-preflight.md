## Actual Temporal operation-driver registration

`BridgeActivities::new` defaults driver to None. `with_operation_driver(Arc<dyn OperationDriver>)` is the accepted assembly seam. `GatewayOperationDriver::{new,with_shared_runtime}` holds a service credential and adapter transport mutex; it maps admission ID to already-prepared exact gateway journals through `Bridge::operation_journal`. It never invents binding/Create/Start intent. Runtime mutex is acquired before journal lookup/dispatch; workflow fencing is checked inside PG dispatch claim. Uncertain journals are queried, not blindly reexecuted. Empty mapping reports `gateway_binding_or_intent_missing`; unregistered driver reports `operation_driver_unconfigured`, not completed execution.

Ticket16 must register an actual driver on the actual SDK Worker activities, prepare its binding/journals first, and prove that Temporal-driven execution changes externally fsynced invocation/effect counts. The accepted SDK subprocess fixture registers MissionWorkflow, TaskWorkflow and BridgeActivities but does not install a driver; separate accepted driver tests exercise public `drive`. Their conjunction is not yet one assembled SDK-to-runtime proof. The current CLI has no workflow-worker/gateway launcher. No privileged bearer enters WorkflowInput/history: worker-local scheduler/read capabilities and command-principal credentials remain separate, and unsupported caller capabilities get durable rejection.

## Authority, roles and accounting

Accepted RoleLead is mission-scoped and may assign Worker attempts, but does not itself represent a replaceable planning episode or replacement-generation fence. RoleVerifier is narrow task/generation/expiry/epoch authority to read assigned evidence and submit verification; it cannot assign an attempt, take Lead authority or mutate Supervisor. No credential-role change may substitute for role-appropriate execution scheduling. Accepted Supervisor creation requires an actual assigned Worker attempt; its uniqueattempt workspace cannot be relabeled an independent verifier environment. Missing role-appropriate execution/admission mapping is a concrete integration requirement; ticket14 is expected to expose admission-related hooks, not presumed to have implemented them.

Core AssignAttempt increments used_capacity, admitted_attempts and admitted_episodes once and stores reservation attempts=1/episodes=1. Supervisor create/start do not charge again; release only refunds the concurrent slot after provenStop and physical deletion, leaving cumulative attempt/episode counts spent. Accepted core has one unique attempt per task, no Episode table, measured-cost/unknown-spend ledger or consumed-repair counter; max_repairs is policy data. A continuation, lead replacement or verifier episode needs an explicit new episode reservation, without another attempt charge. Replacement attempts need distinct ownership/generation and cumulative attempt accounting; accepted schema does not yet provide this lifecycle. Unknown provider spend or OS/preparation survivors must retain capacity and cannot use Supervisor.release as an unrelated provider-cost refund. There is no accepted explicit owner budget-adjustment command.

Finite fixture policy must specify concurrency, attempts, episodes, repairs and deadline, and record actual admissions for worker, lead, verifier and replacement episodes. A possible bounded fixture policy is capacity 2 / max_attempts 4 / max_episodes 10 / max_repairs 2 / deadline 5s with an overall 180s fixture watchdog; these are proposed fixture values, not approved runtime defaults. Prove budget exhaustion and duplicate admissions using public counters. No agent polling episodes while yielded: Temporal services scan/timer, while meaningful answers coalesce one new admitted episode.

## Exact candidate and complete execution proof

Artifact publication fsyncs bytes/directories/manifests before eligible DB references; delayed GC checks references. Acceptance rereads content, exactcurrent candidate/report/spec/generation/base/suite/environment bindings and log digests. `prepare_integration` constructs a real merge-tree/commit-tree fixture candidate and executes checks in a detached fixture worktree, without push or mainline ref update. Test-only independent verifier fetches retained Git bundle, derives commit/tree/firstparent base and executes checks before reporting. Ticket16 needs the same byte-derived behavior behind a bounded trusted adapter: retained bundle/manifest, independent environment, executed mandatory commands and exact-bound retained logs. Changes to base invalidate old proof; preparing an actual new integration candidate is mandatory. The public ArtifactService records and validates assigned-verifier evidence; it does not execute or semantically parse Git bundle contents itself.

Supervisor proof is independently retained: durablePreparing precedes Git spawn; unknown preparation is quarantined. Actual bwrap write scopes enforce individual files/directories and readonly sharedGit. Original gated PID1 certificate, same observer frame, finalized original whole-group evidence or a verified independent namespaceFD establish classification/signaling authority; missing/malformed/permission observations do not establish stop. LauncherPID/lease/worktree path alone is insufficient. Release requires provenStop plus locked deletion and completed deletion before refund. Root kernel diagnosis documents upstream v5.15 inference/vendorhost caveat; finalized processes do not prove asynchronous external service effects completed. Runtime gateway journals and supervised local jobs must therefore both be reconciled; either missing proof blocks combined cancellation/transfer.
