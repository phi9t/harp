* Operating Contract

This file is the active execution ledger for the workstream. Read
[[file:design.md][design.md]], the linked approved design, and the PRD before
claiming a ticket.
For the three-route formal-proof completion phase, also read
[[file:../../superpowers/specs/2026-08-22-crouzeix-three-route-proof-completion-design.md][the completion design]],
[[file:../../superpowers/plans/2026-08-22-crouzeix-three-route-proof-completion.md][the implementation plan]],
and [[file:retrospective-002.md][the execution retrospective]].

Every task must have both:

- one repository ticket below; and
- when it performs a live provider, mathematical evaluation/review, selector,
  formal, or operator-intervention action, one run-local immutable ticket
  created through the runtime ticket contract. Repository plan/code review
  uses its CPFR ticket and review artifact rather than fabricating a model-run
  ticket.

Do not execute a ticket whose =DEPENDS_ON= list is not terminal. =DONE= and a
conditionally justified =CANCELED= are terminal; every other state blocks.
Do not combine tickets in one commit unless a ticket explicitly names the same
commit group. Every commit message ends with:

#+begin_example
Co-authored-by: TRAE CLI <noreply@bytedance.com>
#+end_example

The orchestrator is the sole writer of repository-ticket state and verification
evidence. Every ticket implicitly owns only its own subtree in this file.
Product workers edit only the =Owned Files= listed in their ticket. At closeout,
the orchestrator serially records evidence, refreshes =docs/import-receipt.md=
when tracked bytes changed, stages the owned product files plus this tracker and
receipt, verifies the staged surface, and creates the ticket's focused commit.
It then runs the ticket's post-commit no-edit check against the exact new tip;
that result is operator attestation and is not backfilled into the tested
commit.

Unclaimed work uses =unassigned= for =OWNER=, =AGENT_RUN=, and =MODEL=. Claiming
a ticket replaces those values before implementation. Planned conditional work
uses =BACKLOG=; a false precommitted trigger moves it to =CANCELED= with evidence.
Review repairs that are not already a named ticket require a new =CPFR-R###=
ticket before any tracked edit.

When a file has pre-existing or later-ticket hunks, the owning ticket uses the
CPFR-022 patch map and interactive patch staging. Before verification, the
orchestrator compares =git diff --cached= to the assigned patch IDs and confirms
all unowned hunks are unstaged and byte-identical. Whole-file staging is valid
only when the ticket owns every current hunk in that file. Initially untracked
files use empty-blob base
=e69de29bb2d1d6434b8b29ae775ad8c2e48c5391= and require
=git add -N <path>= before =git add -p <path>=.
