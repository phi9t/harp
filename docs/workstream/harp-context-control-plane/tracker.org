* Current Situation

The approved system design is canonical in
[[../../../knowledge/meta_harness/meta_harness_deep_dive.md][the Meta-Harness deep dive]], section
"Harp context control plane for Trae CLI and Codex CLI".
The dependency-ordered implementation instructions for the observation
milestone are in [[file:plan.md][plan.md]].

Harp currently has:

- a typed Rust CLI with schema-versioned JSON envelopes;
- canonical technical prose under =knowledge/=;
- strict repository, corpus, evidence, and generated-artifact gates;
- secure local state, immutable releases, all four workflow packages,
  deterministic routing and bounded context selection;
- typed Trae CLI and Codex CLI capability probes and invocation builders;
- durable pre-launch episodes, byte-exact provider process capture, and the
  reviewed shared =harp run= lifecycle for both providers.

Harp does not yet own normalized provider events, outcome labels, a sanitized
learning export, ACE/MCE candidate generation or evaluation, App Server
adapters, or a promotion registry. Those remain explicit later work rather
than implied observation-milestone behavior.

* Decisions

** DONE D-001 Harp Is The Shared Control Plane

Harp wraps and observes Trae CLI and Codex CLI. It does not fork either agent
runtime or place cross-run learning on the request critical path.

** DONE D-002 Support All Workflow Families Through Packages

V1 defines =ci_repair=, =code_review=, =dependency_update=, and
=general_coding=. The architecture permits later packages without new provider
branches.

** DONE D-003 Local-First

No hosted service is required. Raw state remains private and repository-scoped
under =HARP_HOME=.

** DONE D-004 Wrapper-First, App-Server-Ready

The first adapters use =exec --json=. App Server integration is a later adapter
behind the same Harp contracts.

** DONE D-005 Observation Only; Suggestions Deferred

The observation milestone cannot generate, install, promote, or migrate ACE/MCE
context candidates or releases.

** DONE D-006 Canonical Prose Stays In Knowledge

The stable design lives in
=knowledge/meta_harness/meta_harness_deep_dive.md=. This tracker owns only
execution state and must not become a duplicate technical authority.

** DONE D-007 Observation Milestone Plan Is Dependency Ordered

The first implementation plan covers =HCCP-001= through =HCCP-005= in
[[file:plan.md][plan.md]]. It defines 13 test-first child sessions, focused
commit boundaries, exact file ownership, and the full offline release gate.
The optimizer, App Server, and promotion layers remain mapped to
=HCCP-006= through =HCCP-011=.

* Risks And Blockers

** Context Attribution Is Initially Partial

The wrapper can prove Harp's supplement and observed provider events, not the
entire effective prompt, selected native skills, or all compaction state.
Episodes must carry an explicit completeness level.

** Provider Surface Drift

Trae CLI and Codex CLI expose similar but non-identical commands and features.
Capability probing and version fixtures are required; command parity cannot be
assumed.

** Raw Trace Sensitivity

Provider streams can contain repository content, user requests, commands,
credentials, and tenant identifiers. Private archive and sanitized export must
remain separate.

** Repository Receipt Churn

Tracked changes alter =docs/import-receipt.md='s payload digest. Refresh the
receipt only after a complete verified implementation landing, not during the
design-only commit.

** Existing Untracked Work

The primary checkout contains unrelated untracked Obsidian files, images,
drafts, and Agentic eval/apply planning documents. Do not stage, delete, or
rewrite them.

* Deferred Work

- Hosted release registry and tenant federation.
- Generated query-time selector code.
- Automatic provider-skill installation.
- Mid-thread release upgrades.
- Full effective-prompt reconstruction without provider support.
- Cloud episode synchronization.
- Automatic promotion before hidden audit, canary, and rollback exist.
- Any claim of recursive successor improvement.

* Completion Criteria

The observation milestone is complete when:

- both providers launch through Harp using one immutable baseline release;
- all four workflow packages route deterministically;
- provider-native security enforcement and repository contracts remain active,
  explicit user-selected native overrides remain visible, and Harp introduces
  no hidden bypasses;
- manifests, context bundles, raw provider streams, Git-state receipts, and
  completion receipts are durable and schema-valid;
