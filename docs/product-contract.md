# Harp product contract

## Product boundary

Harp owns the standalone RSI technical atlas:

- canonical RSI and SICP Markdown under `knowledge/rsi/`, plus the registered
  topic packets under `knowledge/darwin_godel_machine/`,
  `knowledge/meta_harness/`, `knowledge/harness_benchmarks/`, and
  `knowledge/self_improving_agents_survey/`, and
  `knowledge/verified_coevolution_agenda/`, and
  `knowledge/agentic_engineering/`;
- deterministic corpus validation and compilation in `crates/harp/`;
- deterministic diagnosis contracts under `content/diagnostics/`;
- Weng, RLM, SICP, Meta-Harness, Self-Improving Agents Survey, Verified
  Coevolution Agenda, Agentic Engineering, and public implementation evidence
  under `evidence/`;
- remote-only, hash-pinned Crouzeix proof artifacts and four Harp-local
  revision-bound verification receipts under
  `evidence/crouzeix_conjecture/`;
- the runnable SICP evaluator supplement under `labs/sicp-evaluator/`;
- the opt-in Meta-Harness TRAE proposal supplement under
  `labs/meta_harness_trae/`;
- the React Atlas and offline export under `atlas/`; and
- local SQLite full-text search; and
- local context-control releases, context selection, provider capability
  observation, and byte-exact observation of Trae CLI and Codex CLI runs.

Hosted model access, provider authentication, provider security enforcement,
internal infrastructure, and provider-specific CI are outside the product
boundary. Harp observes local provider CLIs without replacing or weakening
their native configuration, repository rules, or enforcement. Harp does not
synthesize or silently widen privileges. Explicit user-supplied native
sandbox, approval, and profile overrides are forwarded to the provider and may
change its behavior.

## Local context control

Context-control state is private and local. Harp uses the first nonempty value
in this order:

1. `HARP_HOME`, used as the complete state-root path;
2. `${XDG_STATE_HOME}/harp`; then
3. `${HOME}/.local/state/harp`.

If all three variables are unavailable, stateful release and run commands fail
rather than choose another location. `providers doctor` remains stateless. The
state root is opened through the secure filesystem boundary and rejects
symlinked, wrongly owned, or group/world-accessible state.

Repository policy is optional and is read only from
`.harp/context-control.json`. A missing file means enabled with no additional
restriction. When present, the strict `harp-repository-policy/v1` object may
disable Harp, limit allowed workflows, pin an immutable release, lower a
workflow's built-in context budget, and declare required verification labels.
Required labels are validated and included in the policy digest, but verifier
execution and outcome enforcement are not implemented in this milestone. The
policy cannot inject prompt text, choose a provider executable or selector,
raise a context budget, or broaden provider authority.

`harp providers doctor` performs bounded local executable, version, and
capability probes. `harp releases compile`, `list`, and `inspect` manage
content-addressed immutable releases. `harp run` supports `trae` and `codex`
across `auto`, `ci_repair`, `code_review`, `dependency_update`, and
`general_coding`.

Provider stdout bytes requested in JSONL mode are copied byte-for-byte and
remain the only process stdout from `harp run`; malformed output is preserved.
Harp lifecycle records and the final episode ID are written to stderr. The
wrapper keeps native provider configuration, repository rules, and enforcement
active. It forwards explicit user-selected native sandbox, approval, and
profile overrides but does not create hidden bypasses.

V1 context-manifest completeness is partial. The pre-launch manifest records
the selected release, Harp context supplement, invocation identity, and pre-run
repository state; it does not claim to reconstruct the provider's complete
effective prompt, native skill selection, retained reasoning, or compaction
state. Raw provider bytes and their completion receipt are separate post-run
evidence.

This milestone is observation-only. Normalized learning export, ACE and MCE
suggestion generation, candidate evaluation, shadowing, canarying, automatic
promotion, and rollback remain deferred.

## Canonical content

The required parity contract is:

- 75 retained concepts;
- 75 coverage entries;
- 93 compiled documents;
- 16 systems;
- nine Weng sections;
- 28 diagnostic fields;
- 29 diagnostic rules;
- 12 diagnostic cases;
- six lessons;
- 84 source-registry rows; and
- 101 evidence edges.

Markdown is the only technical-prose authority. Handwritten TypeScript owns
navigation, state, diagnosis, import/export, and interaction behavior, not
paper mechanisms or result claims.

`knowledge/crouzeix_conjecture/` is a bounded thirteen-document research
packet on AI-assisted theorem discovery, source-level formal verification, and
evidence discipline. It contributes one first-class Atlas route and twelve
auxiliary documents. It does not enter the RSI retained-concept taxonomy,
system registry, Weng sections, diagnostic cases, lessons, or evidence graph.

`knowledge/verified_coevolution_agenda/` is a five-document research-agenda
packet on recursive closure, model-harness coevolution, and assurance for
self-improving systems. It contributes one first-class Atlas route and four
auxiliary documents. It adds eight source-registry rows and three evidence
edges while reusing existing Harp evidence for STOP, Meta-Harness, AHE, DGM,
ADAS, and the Springer Godel Machine record.

## Weng teaching curriculum

`knowledge/rsi/weng-sources/` is the canonical authority for the 42 five-field
source cards. `content/weng-source-cards.tsv` is the exact roster, order, and
assignment matrix for 39 numbered references and three substantive body
links. `content/weng-comparison-matrix.tsv` owns the ordered comparison data,
and `content/weng-claim-ladder.json` owns the five-level claim ladder and its
canonical concept links.

`reference/` and `lessons/` are non-authoritative teaching projections.
`scripts/build_weng_course.py --check` validates the four deterministic
references, and Rust curriculum tests validate the ten lessons. The course
state machine is `building` -> `cards-complete` -> `complete`; `complete`
requires 42 cards, ten lessons, four references, and nine section IDs.
Retrieval begins at `unseen`, and page exposure does not establish mastery.

Teaching files remain outside canonical Atlas compilation unless explicitly
registered later. They do not change the 88-document, 75-concept, or other
canonical corpus counts above.

## Evidence

`harp sources verify` is offline. It verifies:

- captured artifact size and SHA-256 manifests;
- source-specific license records;
- Crouzeix source-receipt identity, rights state, exact evidence-root
  ownership, acquisition-script binding, and local verification-log digests;
- every narrow public-source snapshot and revision identity;
- the offline-complete Meta-Harness project page and dated capture receipt;
- the normalized Meta-Harness TRAE receipt and bounded raw archive;
- the Agentic Engineering and Clanker Constitution dated captures;
- every maintained local evidence locator; and
- Git LFS attributes for binary evidence.

`harp sources materialize` is the explicit network path. It refuses symlinked
roots, dirty checkouts, wrong remotes, Git alternates, replacement refs, config
includes, and revision mismatch before comparing tracked snapshots.

There is no repository-wide license. Captured works are not relicensed.

The Crouzeix bundle keeps upstream manuscript, PDF, TeX, Lean, prompt, and
repository bytes remote-only. Its current source scans found no prohibited
tokens at either pinned Jin revision. Both clean-room Lean builds are recorded
as `blocked`, not failed or passed: the local machine had 4.96 GiB available
against the acquisition policy's 8 GiB minimum for pinned Mathlib cache
materialization. These receipts do not establish mathematical correctness,
manuscript-to-formalization correspondence beyond the named source records,
peer review, or current remote availability.

## Release gate

`mise run verify` is the complete provider-neutral release gate. A clean
`git clone --no-local`, followed by `git lfs pull`, `mise run bootstrap`, and
`mise run verify`, must pass without any other source checkout available. The
gate includes the offline Weng course-builder check, performs no network fetch,
and uses fake provider fixtures without launching an installed Trae CLI or
Codex CLI provider run.
