# Defer Kata adoption for the first kernel

Decision within the owner's approved Git-planning/PostgreSQL-execution baseline.
Read Corenius `963f58b31e518a8162dfe719e386ef9d9843321f` plus accepted10–12
content; evaluated Kata `b70a4306464e319701df30a3b92860289613b15a`.

Keep Git-approved planning input and the existing Markdown tracker for this
kernel. Do not adopt Kata, migrate tickets, install hooks, or build a custom
issue UI. Kata remains an optional future planning/projection adapter, with
PostgreSQL broker execution authority unchanged.

The actual API, credential, claim, close, upgrade and restore probes demonstrate
useful ledger capabilities. The real Kata-to-broker fixture binds source identity
and approved content to one admitted revision; duplicate delivery returns one
assignment receipt. Source edits, closure and projected status do not grant
execution or acceptance authority. This is sufficient evaluation evidence, not
a production adapter or a production cost estimate.

Inference: adoption would add credential provisioning, compatible API/schema
upgrades, immutable amendment review, durable projection delivery/reset handling
and two-store outage/restore reconciliation. Those costs are not yet offset by
a current need for a new issue UI. Defer avoids adding these dependencies before
the approved durable kernel and live recovery proofs exist; it does not reject
Kata's future reuse or replace the requested evaluation with static research.
