## Public integration seam and limits

Bridge exposes register/lookup/enqueue/apply_with_capability/progress/next/close/pending_wakeups/deliver/operation_journal/observe_execution. Register allocates only with explicit Owner authority and exact prior generation; terminal commands are rejected, not silently restarted. BridgeActivities::with_operation_driver registers Activity-side runtime work. GatewayOperationDriver provides an explicitly shared runtime gate and local queued-count observability; it queries exact stable admission journals and dispatches only already-prepared intents with the transactional workflow guard. Kernel16 must provision actual runtime/store binding, prepare Gateway Create/Start intents and register that driver. Missing driver/binding and closed orchestration retain named limitations, never provider completion or task acceptance.

This is single-host fail-closed control, not transport-level exactly-once, live Trae, cgroup or multi-host failover proof. Close/replacement before a durable dispatch claim fences it; close after a committed claim cannot revoke the in-flight RPC. Accepted gateway/supervisor owns physical cancellation and uncertainty.
