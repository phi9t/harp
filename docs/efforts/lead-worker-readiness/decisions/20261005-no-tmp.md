# Decision: the host's /tmp is banned for agents

Date: 2026-10-05, 19:35 UTC.
Authority: the owner, in the lead session: "let's ban the use of "/tmp" altogether and get the agents to use
other dirs as temp dirs".

## Accepted direction

Agents, and the tools and tests they run, do not use the host's `/tmp`. They use other directories as temp
directories.

## Lead's reading, where the words leave room

- Which directory: for a worker, a directory inside its own run directory, set by the launcher through
  `TMPDIR`, `TMUX_TMPDIR` and `TMPPREFIX`. For an agent working by hand on this machine, a directory it owns
  under `/data02/home/philip.yang/devx/tmp/`.
- The ban is about the host's `/tmp`. A capsule's private tmpfs mounted at `/tmp` inside the capsule is not
  the host's `/tmp`.
- What cannot be changed from this repository is recorded, not hidden: the Codex sandbox creates mount
  points under the host's `/tmp` when it starts a command (observed 2026-10-05:
  `bwrap: Can't mkdir /tmp/.aws`).
- Scope here: this repository's tools, tests, launcher and worker briefs (ticket 22) and its `AGENTS.md`.
  Other repositories and other agents' existing worktrees under `/tmp` are the owner's to direct; the
  disk-cleanup worker only proposes them.
